# 办公室里的手机

- 日期：2026-10-21
- 相关：项目所有者要求为玩家角色加入可随时取出的手机，屏幕出现在场景右下方；
  手机内先加入仿微信排布的聊天应用，群聊与所有已创建的 Agent 都能私聊或群聊，
  聊天能力与场景外一致；不改变多智能体协作逻辑。

## 为什么

办公室里的当面对话受位置限制：要先走到同事身边。手机让玩家在任何楼层、任何位置
都能打开同一个会话（群聊或私聊），发送和查看仍然走现有 Session，工具执行、权限、
任务派发、回传和回工位规则完全不变。手机只是第二个界面，不新建通道。

## 调研

完整调研、来源与不确定项见[手机调研](2026-10-21-office-phone-research.md)。

- 微信移动端（2024–2026）：底部 Tab 最多 2–5 个；聊天列表按最近活动排序，行内
  40pt 圆角方头像、名称、最后一条消息、时间与未读红点；聊天页顶部返回、标题
  （群聊带成员数），自己的消息在右、对方在左，群聊显示发送者名字，消息间隔约 5
  分钟显示时间，底部输入栏负责文字、语音、表情与附件；联系人页按字母分组并带
  Group chats 入口。微信没有已读回执，输入中提示只在私聊出现。官方 WeUI 取色
  （品牌绿 #07C160、我的气泡 #95EC69、页面 #EDEDED、红点 #FA5151）只作为结构
  参照，本项目的视觉与图标必须原创；白字压 #07C160 的对比度只有 2.38:1，不复用。
- 游戏内手机：GTA V 的 iFruit、赛博朋克 2077、女神异闻录 5、星露谷物语、
  动物森友会 NookPhone、绝区零 Inter-Knot、鸣潮 WavesLine、无限暖暖 Pear-Pal、
  Watch Dogs、奇异人生、看火人都把手机做成“镜头一角出现的一块屏幕”。其中
  GTA V 与 Persona 5 让角色真正举起手机、屏幕从画面下方升起；NookPhone 提供了
  最好的首页/应用网格范式；看火人的选择界面与右下角冲突，说明手机应当独占该角。
  常见做法：打开时锁定玩家走位、世界继续运行、PC 直接用键盘输入、手机打开时其它
  HUD 让位。
- 结论：手机屏幕固定在场景右下角，宽度约 280–344px，打开时角色站定并举起手机，
  HUD 淡出并停止响应，镜头工具、附近提示与当面对话面板让位；聊天内容复用原生
  输入区，外观改为游戏内风格；手机打开时世界与 Agent 回合继续运行，只是玩家停下。

## 已定的行为

### 取出手机与收起

- 右上角 HUD 地图下方的 **Phone** 按钮（含 `P` 键提示与未读点）随时取出手机。
  打开后角色站定、面向镜头、右手举着手机；关闭后恢复移动。打开时暂停玩家移动、
  点击地面和 E 交互；右上角 HUD 淡出、停止响应，镜头工具、附近提示、操作提示、
  欢迎卡和当面对话面板隐藏，关闭后恢复。世界与 Agent 回合继续运行。
- 打开手机时先关闭地板目录；正在进行的休闲活动直接结束。会议、大屏、电梯运行和
  装饰面板打开时不提供手机入口。换楼层、返回普通聊天、场景销毁时收起手机。
- 手机外观：圆角机身、状态栏（时间、信号、电量）、壁纸、时钟与日期、一个聊天应用
  图标（原创语音气泡图形，不使用微信标志）、Home 指示条；首页不设 Dock，也不在
  机身内放收起按钮，底部只保留 `Esc` 收起提示。应用内 `Esc` 逐级返回（聊天 →
  列表 → 首页 → 收起）。
- 打开手机为 60–260ms 上浮缩放动画，角色手臂同时抬起；Quiet motion 与系统
  reduced-motion 下只保留 120ms 透明度。

### 手机里的聊天应用

- 首页点聊天图标进入应用；顶部标题，底部两个 Tab：Chats（最近会话）与 Contacts
  （Group chats + 全部 Agent 好友）；支持按名称、角色、最后消息搜索。
- Chats 为空会话显示引导文案；每行显示头像（Agent 用现有像素立绘，群聊用成员头像
  叠层）、名称、最后一条消息、时间、未读点。群聊与私聊都排在同一个列表里。
- 点行进入聊天页：顶部返回、标题、私聊/群聊说明；消息区为自己的右侧绿色气泡、
  对方的左侧白色气泡；群聊显示发送者名字与头像；消息间隔超过 5 分钟显示时间；
  支持 Markdown、思考、工具调用与结果、图片、文件、长消息、流式输出和失败提示；
  上滑到顶加载更早历史，回到底部可回到最新。
- 输入区继续使用原生 `conversation.content` Factory：附件、语音、模型、队列、
  提问卡、密钥卡、斜杠命令、@ 提及全部保留；样式压缩到手机宽度。
- 私聊打开该 Agent 当前 Session 分段；群聊打开群自身的 Session。发送后与场景外
  完全相同地进入既有 Bot 回合。场景内可见的结果（回工位、头顶预览）沿用现有
  `watchOfficeSession` / `officePresence` 逻辑，不新增 host 接口。
- 同一 Session 不能同时挂两个输入区：若某会话已开在当面对话、会议或大屏上，
  手机里的该行标记为 “Open on the office screen”，点击只收起手机，不重复挂载。
  会议/大屏/电梯打开期间不打开手机，避免和会议输入区冲突。

### 手机浏览器

- 首页新增第二个应用 **Browser**。点开后是手机比例的浏览器：顶部返回、前进、
  刷新、地址栏、外开按钮与菜单，地址栏下方是占满手机屏幕剩余区域的页面视图。
- 在网页里的 iframe 无法要求手机 User-Agent，所以页面由插件 host 以手机 UA 抓取，
  交给手机内的沙箱 iframe 显示（`srcdoc`）。页面资源通过 `<base>` 从原站加载；页内
  链接和 GET 表单通过 `postMessage` 回到手机地址栏，历史、前进后退与刷新由手机维护。
  抓取走运行 DSH 的这台电脑：优先读取环境变量或 Windows 系统代理（与 Chrome 使用同一
  代理），请求移动版本；本机与局域网地址直连。手机 UA 不保证所有网站都返回可用页面。
- 地址栏接受 http(s) 地址、主机名或搜索词，非 http(s) 协议与云元数据地址不执行；
  搜索词统一打开 Google，Google 页内 GET 搜索也保留原查询，不自动更换搜索引擎。
  Google 返回验证、限流或必须启用完整浏览器的页面时，保留查询并显示可重试的错误页，
  可直接在系统浏览器打开同一地址；这不代表手机沙箱已通过 Google 的验证。
- 移除原页面相互冲突的 viewport，使用唯一的 device-width 视口；约束桌面固定宽度，
  图片随手机缩放，表格与代码块在自身区域滚动。正文维持 13–18px、输入控件至少 16px，
  标题最多 28px，动态插入的文本也重新适配；不通过整体缩小桌面网页来塞入屏幕。
- 起始页提供 Google、Bing、Wikipedia 快捷入口、本机网络说明与沙箱限制提示；菜单
  提供 Reload、Open in system browser、Copy address、Home page、Back to phone，
  工具栏的“在系统浏览器打开”可随时打开原站。
- 限制：沙箱不允许 cookie/存储，因此登录与依赖登录态的站点不能使用；大量依赖同源
  XHR/fetch 的脚本站点会降级或只显示静态内容；页面内 JS 主动改地址、POST 表单与
  下载可能需要系统浏览器。返回内容上限 4MB，超时 15 秒。
- 地址解析与代理设置解析均有单元测试；host 只新增 `mobile-page` 抓取端点，不读写
  Bot 的浏览器存储分区，也不改动 DSH。
